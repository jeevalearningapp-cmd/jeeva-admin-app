📊 Current Architecture Analysis
I've analyzed your codebase and here's how it currently works and what needs to change:

CURRENT IMPLEMENTATION
1. Module Fetching (Dynamic):

Files: src/api/modules.ts, app/(tabs)/courses.tsx, app/(tabs)/practice/index.tsx, app/(tabs)/learning/index.tsx
Pattern: Fetches all active modules from database via getModules()
Usage: Practice, Learning, and Mock Exam screens all dynamically load modules
2. Question Retrieval (Lesson-Based):

Files: src/api/practice.ts, app/(tabs)/practice/quiz.tsx, app/(tabs)/mockexam/index.tsx
Pattern:
getQuestionsByLesson(lessonId) - filters by lesson_id
getQuestionsByTopic(topicId) - joins with lessons table to filter by topic_id
Problem: Tightly coupled to lesson hierarchy - won't work with tag-based filtering
3. Flashcard Organization (Lesson-Based):

Files: src/api/modules.ts (lines 149-175)
Pattern:
getFlashcardsByLesson(lessonId) - filters by lesson_id
getFlashcardsByTopic(topicId) - joins lessons table
Interface: lesson_id: string (line 55)
Problem: Hardcoded to lessons instead of topic categories
4. Learning Progress (Lesson-Based):

Files: src/api/modules.ts (lines 177-257), src/api/learning.ts
Tables: learning_completions table with lesson_id foreign key
Pattern: Tracks completion per lesson, calculates topic progress by counting completed lessons
Problem: No quiz passing requirements or topic-based progress tracking
